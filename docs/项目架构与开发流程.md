# Personal AI Workbench 项目架构与开发流程

> 生成时间：2026-08-11 · 覆盖范围：仓库根目录（Electron 壳 + Workbench 应用 + 示例 Vault）

## 1. 项目概述

**Personal AI Workbench** 是一个本地优先（local-first）、直接读取 Obsidian 风格 Markdown Vault 的个人 AI 知识工作台。它把 Raw 素材、Wiki 知识、阅读、灵感、内容生产、社媒研究和账号数据放进一套可读的 Markdown 目录中，由 Workbench 负责索引、搜索、阅读和图表展示。

本仓库是**公开、隐私安全版**：

- 应用代码只存放在 `Workbench/`，不内嵌任何个人内容；
- 仓库级 `个人知识库/` 是完全虚构的 synthetic demo，用于演示；
- 真实用户的 Vault 必须放在仓库之外，通过 `PERSONAL_DASHBOARD_VAULT_ROOT` 指向；
- 发布前必须通过 `npm test`、`npm run build`、`npm run privacy:scan` 三道门禁。

### 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19 + React Router 7 + Vite 6（JSX，无 TypeScript） |
| 图表/动画 | recharts、d3-force、gsap、motion |
| 后端 | Node.js 原生 `node:http` + Vite 插件挂载 API（无 Express） |
| 桌面壳 | Electron 33（仅做启动器，加载本地 HTTP 服务） |
| 托管（可选） | Cloudflare Worker SPA 回退 + OpenAI Sites 配置 |
| 测试 | Node 内置 `node:test`（无 Jest/Vitest） |
| 数据校验 | zod、gray-matter、minisearch（本地全文搜索） |

环境要求：Node.js 22+。

## 4. 架构模式与数据流

### 4.1 一体化前后端

- **开发模式**：`vite` 启动，`workbenchApiPlugin()` 把 `/api/*` handler 挂到 Vite dev server；页面与 API 同源。
- **生产模式**：`server/standalone.mjs` 用 `node:http` 起裸服务器，复用同一个插件 handler，同时托管 `dist/client` 静态产物（含 SPA fallback）；由 esbuild 打包成单文件 `server-bundle.cjs`，运行期不再需要 node_modules。
- **桌面壳**：Electron 主进程 spawn Node 子进程启动服务，等端口 5173 就绪后加载 `http://127.0.0.1:5173`，退出时杀掉子进程。

### 4.2 数据流

```text
Vault (Markdown/JSON)
  → vault-index.mjs 构建内存索引（含全文搜索 minisearch）
  → vault-sync.mjs 监听文件变化，经 SSE /api/vault/events 推送
  → React 页面（useVaultSync 按 scope 增量刷新）
  → API 失败时降级到 src/data/fallback.js
```

- 每个页面请求都会带 `revision`，Vault 变化时按 `affectedScopes`（overview/graph/wiki/materials/...）定向失效重取。
- 前端通过 `src/lib/api.js` 统一请求，`withFallback` 保证离线/服务不可用时页面不空白。

### 4.3 双模式构建

- **本地版**（默认）：`VITE_WORKBENCH_HOSTED !== "true"`，开放本地专属能力（社媒洞察、阅读笔记、Codex 工作流、Wiki 导入）。
- **托管版**：`npm run build` 以 `VITE_WORKBENCH_HOSTED=true` 构建纯静态站点，配套 `worker/index.js`（Cloudflare Worker SPA 回退）与 `.openai/hosting.json`。

### 4.4 安全与隐私边界

- 服务只监听 `127.0.0.1`（`vite.config.mjs` 与 `standalone.mjs` 均写死 loopback）。
- `server/security.mjs`：路径白名单校验（`10_raw`/`40_topics`/`50_scripts`/`90_runs`/`wiki`）、相对路径/符号链接/大小限制检查，禁止越出 Vault 根目录。
- 索引器显式跳过 `Brainstorm/`、`90_runs/`、`30_self_media/public-account/`；相关 API 路由返回 `FEATURE_NOT_INCLUDED`。
- Codex 任务使用 `--sandbox read-only` / `workspace-write` + `--ephemeral`，草稿写入需用户确认。
- 缺失数据保持缺失（`null`/空数组），绝不虚构为 `0`；demo 数据必须显式标记。

## 5. 数据契约

### 5.1 Vault 结构（示例承诺的范围）

```text
your-vault/
├── 10_raw/                 # 原始材料（文章、书籍、思考、社媒洞察）
├── 30_self_media/douyin/   # 可选：抖音固定数据层 current.json
├── 40_topics/ideas/        # 灵感
├── 50_scripts/             # 内容成果
└── wiki/
    ├── concepts/           # 概念
    └── frameworks/         # 框架
```

- `个人知识库/.workbench-demo.json`：`{schemaVersion:1, demoMode:true}` 是 demo 标记，只有显式存在才开启演示模式。
- `个人知识库/AGENTS.md` 定义了 LLM Wiki 维护 Schema（ingest/query/lint 流程、页面分类、frontmatter、日志规范）。

### 5.2 抖音数据契约

- 运行时数据：`30_self_media/douyin/current.json`；
- 字段模板：`Workbench/templates/douyin/current.template.json`；
- 契约说明：`Workbench/templates/douyin/README.md`；
- 门槛：`schemaVersion=1`、`dataQuality.status` 非 failed、`douyin.available=true`；
- 生成命令：`npm run demo:generate`（确定性生成，只重写公共 demo 数据）。

### 5.3 每日热点策略

- 默认策略：`Workbench/config/attention.default.json`（5 个中性关注域 + 阅读分层规则）；
- 个人覆盖：复制 `attention.local.example.json` 为 `attention.local.json`（已被 Git 忽略）；
- 数据源：`shared/ai-hot.mjs` 中的匿名公共 API（15 分钟缓存、12s 超时）。

## 6. 测试体系

- 测试框架：Node 内置 `node:test` + `node:assert/strict`，测试文件放在 `Workbench/tests/*.test.mjs`。
- 全量测试：`npm test` = 先 `npm run build` 再串行跑全部测试。
- 定向测试脚本（均为子集，便于快速回归）：
  - `test:authenticity`（数据真实性）、`test:ui-information-gate`（信息门）、`test:daily-hot`；
  - `test:social-insights`、`test:materials`、`test:books`、`test:vault-sync`；
  - `test:graph-motion`、`test:reader-*`（anchors/ui/api/explanations/notes）、`test:wiki-ingest`、`test:sites`。
- 覆盖重点：Vault 索引与隐私跳过、demo 模式标记、图模型/动画、阅读器锚点与笔记、材料阅读状态、书籍进度、社媒洞察解析、SSE 作用域失效、Wiki 导入流水线、Sites Worker 回退。

## 7. 开发流程

```bash
# 1) 安装依赖（根目录是 Electron 壳；核心依赖在 Workbench/）
cd Workbench
npm install

# 2) 启动开发服务器（Vite + API 同源，默认读取 ../个人知识库）
npm run dev

# 3) 桌面版启动（根目录，Electron 自动拉起 dev server）
#    回到仓库根目录
cd ..
npm install
npm run dev
```

### 7.1 连接自己的 Vault

```bash
cp .env.example .env
# 填写 PERSONAL_DASHBOARD_VAULT_ROOT=/absolute/path/to/your-vault
```

重启开发服务器生效；真实 Vault 保持在仓库外，避免误提交个人资料。

### 7.2 常见开发动作

- 改关注域策略：编辑 `Workbench/config/attention.local.json`（本地覆盖，不入库）。
- 重新生成抖音演示数据：`npm run demo:generate`。
- 前端页面开发：改 `Workbench/src/`，Vite HMR 即时生效。
- 后端 API 开发：改 `Workbench/server/`，在 `vite-plugin-workbench.mjs` 中注册路由。

## 8. 构建与发布流程

### 8.1 标准发布门禁（AGENTS.md 强制）

```bash
cd Workbench
npm test          # 构建 + 全量单测
npm run build     # VITE_WORKBENCH_HOSTED=true 构建托管版站点 + Sites 产物
npm run privacy:scan   # 全仓库隐私扫描（个人路径/凭据/私库标识/密钥）
```

`privacy:scan` 检查项：macOS 家目录路径、已知私有 Vault/产品标识、`api_key`/`token`/`secret`/`password` 赋值、私钥块；扫描覆盖整个仓库（含 `个人知识库/`），排除 `.git`、`dist`、`node_modules`、二进制文件。

### 8.2 桌面版（Windows NSIS）发布链路

```text
scripts/build-production.ps1
  1) npx vite build          → Workbench/dist/client（自包含前端）
  2) npx esbuild standalone  → Workbench/server/server-bundle.cjs（单文件后端，CJS）

scripts/prepare-seed.ps1
  打包 server-bundle.cjs + dist/client + Vault → build/seed.tar.gz + seed-version.txt

npm run dist（根目录，electron-builder --win nsis）
  产物：release/Personal Workbench Setup *.exe
  seed.tar.gz 作为 extraResources 打进安装包
```

Electron 首次启动把 seed 解压到 `userData/PersonalWorkbench/workbench-runtime`，之后每次启动校验 `seed-version.txt`，版本变化时只重建 `Workbench/`、保留用户 Vault。

### 8.3 托管版（Sites）

- `npm run build` 产物：`dist/client` + `dist/server/index.js`（worker）+ `dist/.openai/hosting.json`；
- 静态托管下 `localWorkbench=false`，自动隐藏社媒洞察等本地专属页面。

## 10. 关键约定速查

- **数据边界**：真实用户数据永不进公共仓库；示例一律从零虚构并标注。
- **功能边界**：Brainstorm、运行档案、微信公众号模块不公开；索引器与 API 双重隐藏。
- **缺失语义**：缺失字段保持缺失，不填 `0`/假值。
- **回退语义**：前端 fallback 数据只保证“不空白”，不含统计值。
- **网络边界**：默认 loopback-only；本地变更 API 不对局域网开放。
- **本地覆盖**：`.env`、`config/attention.local.json` 等被忽略文件承载个人配置。
