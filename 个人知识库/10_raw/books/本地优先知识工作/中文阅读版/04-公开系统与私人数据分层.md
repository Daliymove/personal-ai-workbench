# 公开系统与私人数据分层

> 这是一章完全虚构的演示文本，不对应任何已出版作品。

个人工作台最容易获得关注的时刻，往往也是隐私风险最高的时刻。完整界面能够展示系统价值，但界面背后的标题、时间、路径、账号曲线和历史判断，也可能组合成一份非常具体的个人画像。

## 删除姓名还不够

脱敏常被误解为把姓名换成“用户 A”。事实上，真实的发布时间序列、作品标题组合、客户行业、文件路径和异常指标都可能重新识别来源。把一条真实记录改几个字段，不等于生成了公开示例。

更可靠的做法是从零编写 synthetic demo。示例人物、任务、日期、ID、指标和来源都不从真实记录派生。数据之间仍保持逻辑一致，让图表能够工作，但它不再描述任何真实个人或账号。

## 三类应该分开的资产

第一类是公共程序：界面、索引器、数据契约和通用算法。第二类是默认配置：为了让软件第一次运行而提供的中性值。第三类是私人实例：个人资料、关注词、客户信息、账号数据和运行历史。

公开仓库可以包含前两类，但私人实例应保存在被 Git 忽略的本地文件或仓库之外。这样，使用者既能看到系统如何运行，也不会误以为作者的个人策略是唯一答案。

## 示例必须诚实

一个完整演示数据集应该覆盖页面需要的全部字段，否则用户只会看到空图表；但它必须在数据文件和界面上同时标记为示例。只在 README 里写一句“数据已脱敏”不够，因为截图可能脱离 README 单独传播。

诚实的示例还应保留空值语义。真实系统没有某项数据时应显示未知，而不是自动填零；synthetic demo 可以为了展示图表填满字段，但必须让使用者知道这些数值不能作为行业基准。

## 发布前的五个检查面

检查工作区中准备提交的文件；检查 Git 历史是否曾经出现秘密；检查图片和录屏是否带有账号信息；检查测试夹具是否从真实数据复制；检查构建产物和 source map 是否包含绝对路径或环境变量。

自动扫描可以发现常见路径、密钥格式和身份标识，但它不能识别所有语义泄漏。最终仍需要人工回答：一个熟悉作者的人，能否仅凭这些示例判断出真实项目、客户或账号？

## 本章小结

开源的是可复用能力，不是个人生活的镜像。公共程序提供结构，中性配置提供起点，私人实例保留个性。把三者分层，既能让别人真正使用，也让作者在分享作品时不必用隐私交换可信度。
